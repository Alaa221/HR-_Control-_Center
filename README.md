# HR Control Center – موقع الموارد البشرية (Flask)

نسخة ويب من داشبورد Power BI الخاص بـ GPS HR System.

## التشغيل
```bash
pip install -r requirements.txt
python app.py
```
ثم افتحي: http://127.0.0.1:5000  (على ويندوز: دوسي مرتين على `run.bat`)

## الصفحات
- `/` الداشبورد: كل كارد ينقل لصفحة تفاصيل `/kpi/<key>` (رسوم توزيع + جدول + بحث + فلاتر + تصدير CSV).
- `/org/sector` و`/org/management` و`/org/department` و`/org/job`: الهيكل التنظيمي، والضغط على أي مجموعة يعرض موظفيها.
- `/employees` بحث وفلترة وتصدير.
- `/profile` ثم `/employee/<code>`: ملف كامل + قائمة المستندات + تنبيهات الموظف.
- `/leaves`: حساب أرصدة الإجازات للموظفين الفعّالين، تسجيل الحركات مباشرة في قاعدة البيانات، وتوثيق طريقة تعويض العمل الإضافي.
- `/contracts` و`/probation` و`/documents` و`/alerts`: كروت حالة قابلة للضغط + جداول.

اللغة (English / العربية) من الزر أعلى الصفحة، والاتجاه RTL تلقائي.

## تقرير الموظف + All Summary
- `/attendance/report`: اختاري القسم فيظهر التقرير التفصيلي لكل موظفيه فورًا (أو اكتبي موظف واحد). يمكن الانتقال من التقرير إلى إجازات الموظف والعكس. في تقرير الحضور والملخص فقط، يُطرح ساعة من بصمة الحضور الأولى يوم 2026-11-01 لجميع الموظفين، دون تعديل بصمات الانصراف أو مصدر البيانات. كما تُصحح ساعة بصمات المصدر خلال فترة التوقيت الصيفي؛ بعد التحول للتوقيت الشتوي لا يُخصم أي ساعة. صفحة الحضور اللحظي تظل على وقت المصدر.
- زر **All Summary** يفتح `/attendance/summary`: صفحة مستقلة بنفس شيت Summary (موظف في كل صف + صف إجماليات)، وفيها تحميل Excel (RTL وبنفس المعادلات) وطباعة.
- معادلات الخصم: **ساعات الخصم = إجمالي التأخير والانصراف المبكر** ، **أيام الخصم = إجازات بالخصم + أيام الغياب + (فقدان البصمة × 0.25)**.
- الإجماليات بتتجمع من الدقايق مش من النصوص، والبصمات بتتسحب على دفعات (`A.fetch_range`) عشان سقف `max_rows` ما يقصش بصمات ويطلّع غيابات وهمية.

## البيانات
- ملفات Excel وقواعد البيانات المحلية غير مضمنة في هذا المستودع لحماية بيانات الموظفين. ضعي ملفات البيانات محليًا بالأسماء المتوقعة: `data/GPS - HQ Data Base - Active.xlsx` و`Vacations_2026.xlsx`. تُحفظ حركات الإجازات محليًا في `data/hr_leaves.sqlite3`.
- حركات الإجازات والأذونات تُزامَن من ورقة `Records` في `Vacations_2026.xlsx` عند تغيير الملف؛ ويُحتسب كل تاريخ في أعمدة الإذن الأول/الثاني ساعتين في تقرير الحضور.
- الرصيد السنوي والعارض للسنة الحالية يُحسبان وفق أعمدة الاستحقاق والمستخدم والإضافي في ورقة `Records`؛ والحركات الجديدة في البرنامج تُخصم من الرصيد. يستخدم التطبيق منطقة `Africa/Cairo` تلقائيًا، بما فيها التحول بين التوقيتين الصيفي والشتوي.
- الحسابات (فترة الاختبار 90 يوم، حالة العقد، السن، مدة الخدمة، التنبيهات) بتتحسب من تاريخ اليوم داخل `data.py`.
- الصفوف الفارغة (بدون اسم) بتتجاهل تلقائيًا.
- أرصدة الإجازات تُحسب شهريًا من تاريخ التعيين وتُعرض سنة ميلادية بسنة ميلادية: 15 يومًا في أول سنة، ثم 21 يومًا، و30 يومًا بعد 10 سنوات خدمة/تأمينات أو بعد سن 50. كل استحقاق سنوي يتضمن 7 أيام عارضة، والباقي اعتيادي. لا يُرحّل الرصيد غير المستخدم من سنة إلى التالية، ويبدأ الاستخدام بعد إتمام 3 أشهر. حفظ الحركة يضيفها مباشرة إلى السجل؛ تحويل العارضة الزائدة إلى اعتيادي يتطلب اسم المدير وتأكيد اعتماده.
- لإعادة إرسال طلبات الاعتماد القديمة المعلّقة عبر Power Automate، أنشئي Automated cloud flow بمحفز **When an HTTP request is received**، ثم أضيفي إجراء **Office 365 Outlook — Send an email (V2)**. استخدمي `recipient` كعنوان To، و`subject` كعنوان الرسالة، و`body_html` كالمحتوى (HTML). احفظي التدفق وانسخي عنوان HTTP POST الخاص بالمحفز إلى متغير البيئة `HR_POWER_AUTOMATE_URL` على جهاز/خادم تشغيل التطبيق. رابط المحفز يحتوي بيانات اعتماد سرية، لذا لا تضعيه في الكود أو ترسليه بالبريد، واستخدمي متغير بيئة/مخزن أسرار. عند ضبط `HR_POWER_AUTOMATE_URL` يُستخدم Power Automate بدل SMTP.
- يمكن ضبط بريد المدير الافتراضي بمتغير البيئة `HR_LEAVE_MANAGER_EMAIL`. بديلًا عن Power Automate، يمكن إعداد SMTP للطلبات القديمة بمتغيرات البيئة `HR_SMTP_HOST`، `HR_SMTP_PORT` (587 افتراضيًا أو 465)، `HR_SMTP_USER`، `HR_SMTP_PASSWORD`، واختياريًا `HR_SMTP_FROM`. لا تضعي كلمات المرور أو عناوين التدفقات السرية داخل ملفات المشروع.
- سجل الإجازات وسياسات التعويض محفوظة في `data/hr_leaves.sqlite3`. يمكن تسجيل فترة من/إلى، وتُحسب أيام الإجازة بالتقويم بما يشمل أيام الراحة الأسبوعية، وتظهر الحركات في ملف الموظف وتقرير الحضور وملخص القسم. تحويل العارضة الزائدة إلى اعتيادي يتطلب اسم المدير وتأكيد اعتماده؛ الإذن بحد أقصى ساعتين، وإذنان شهريًا، والمرضي المدفوع بحد 90 يومًا خلال 3 سنوات.
- السياسة المالية لتعويض الجمعة/السبت والمواسم تُوثق لكل موظف؛ إضافة يوم لرصيد الإجازات تتم منفصلًا بكود `ADA` بعد اعتماده.

## تعديل سريع
- أرقام الأيام: `PROB_DAYS` و`PROB_SOON` و`CONTRACT_SOON` في `data.py`.
- النصوص والترجمة: `i18n.py`.  الكروت: `_kpis()` في `app.py`.  الألوان: `:root` في `static/css/style.css`.

## صفحة الحضور اللحظي (Live Attendance)
تسحب البصمات مباشرة من SQL Server (LocalDB) بدل تنزيل ملفات من الـ ZK.
تعرض البطاقات إجمالي الموظفين النشطين المطابقين للفلاتر، وعدد حركات البصمة الخام المطابقة للتاريخ والفلاتر المحددة.

1. `pip install -r requirements.txt` (فيه `pyodbc`) + لازم يكون مثبت **ODBC Driver 17 for SQL Server** على الجهاز.
2. اضبطي متغيرات البيئة المطلوبة للاتصال، مثل `ATT_MDB` لمسار ملف Access أو `ATT_SOURCE=sqlserver` و`ATT_SERVER` و`ATT_DB` و`ATT_USER` و`ATT_PASSWORD` لاتصال SQL Server. لا تضعي كلمات المرور أو مسارات بيانات العمل في ملفات المشروع.
3. اختاري `preset`: `zkbiotime` أو `zktime` أو `custom` (لو شكل الجداول مختلف).
4. مش عارفة اسم القاعدة أو الجداول؟ شغّلي `python tools/discover_db.py` وابعتي الناتج.
5. للمعاينة ببيانات وهمية: `set ATT_MODE=demo` ثم `python app.py`.

### مصدر ملف ZKTime (ATT2000.MDB)
الافتراضي دلوقتي `source = "access"`، والمسار يُضبط بمتغير البيئة `ATT_MDB`. الملف بيتفتح **قراءة فقط** فمفيش خطر على برنامج الـ ZK.
المطلوب: **Microsoft Access Database Engine 2016 Redistributable** بنفس نوع بايثون (64 أو 32 bit).

### سحب البصمات من أجهزة ZK (بيكتب في ATT2000.MDB)
- مع تشغيل `python app.py` بيبدأ محرك سحب في الخلفية: بيقرا الأجهزة من جدول `Machines` في الـ MDB (نفس ZKTime 5.0) ويسحب منها كل دقيقة ويضيف البصمات الجديدة بس (من غير تكرار مع اللي ZKTime نزّله).
- حالته ظاهرة في بانل **"سحب البصمات من الأجهزة"** أعلى صفحة `/attendance`: عدد الأجهزة المتصلة/اللي مش بترد، زر "اسحب دلوقتي"، وإيقاف/تشغيل، وقايمة بحالة كل جهاز.
- الإعدادات في `att_config.py`: `sync_enabled` و`sync_seconds` و`sync_workers` و`sync_timeout`.
- محتاج `pip install pyzk` (مضافة في requirements.txt). السحب شغال بس مع `source = "access"`.
- البصمات بتتسجل بـ `SENSORID` = رقم الجهاز و`sn`، واسم الجهاز في الصفحة بيتحدد بالـ sn.
- بصمات موظفين مش موجودين في `USERINFO` أو بتاريخ مستقبلي بتتجاهل.
- ملاحظة: القراءة في الصفحة لسه بتفتح الملف للقراءة فقط، والكتابة بتتم بس من محرك السحب.
